# Sales BI Assistant

A small, local business intelligence app for asking natural-language questions about the supplied sales transactions. It uses only Python's standard library and SQLite; it needs no API key or external service.

## Run it

Requires Python 3.10 or later.

```bash
python app.py
```

Open <http://127.0.0.1:8000>. On startup, the app imports `data/sales.csv` into `data/sales.sqlite3`. It recreates the transaction rows on each launch, so the CSV is the source of truth.

## Supported questions

- Total revenue
- Product with the highest revenue
- Monthly revenue trend
- Region with the highest sales
- Revenue change between two named months or `YYYY-MM` months

Try the example buttons in the UI. The JSON API accepts `POST /api/ask` with `{"question":"..."}`. `GET /api/health` reports database status. Unsupported questions return HTTP 400 with a useful explanation.

## Data and calculation

The `sales` table stores one validated transaction per row, with an index on `order_date`. Dates are normalized to ISO format. The database calculates revenue as `quantity * unit_price - discount_amount`; only `Completed` transactions with positive quantity and price and a nonnegative discount no larger than gross sales are imported. Invalid, duplicate, returned, and zero-quantity rows are excluded and counted in `import_audit`. A generated revenue column keeps the formula consistent. This dataset contains 51 source rows; one returned transaction and two invalid/non-revenue rows are excluded.

All analytics use fixed, read-only SQL statements. The question interpreter maps recognized wording to one of five allow-listed intents and extracts month parameters. It never executes SQL supplied by a user or generated by a model. The SQLite connection is set to `query_only` for answer queries. This makes the app deterministic and avoids unsupported answers, but it is not a general-purpose conversational LLM.

## Architecture

```text
Browser UI  →  POST /api/ask  →  intent interpreter  →  allow-listed SQL  →  SQLite
                                      ↑                      ↓
                                 user question       structured figures + answer
CSV ── startup import and validation ────────────→ sales table
```

## Tests

Run the included automated tests with:

```bash
python -m unittest discover -s tests -v
```

Coverage includes total revenue, top product, monthly trend, top region, month comparison, unsupported and destructive questions, and API input validation.

## Known limitations

- The interpreter recognizes a bounded set of English question patterns and month names. It does not support arbitrary filters, forecasting, or general SQL.
- Bare month names default to 2026 because that is the year in the supplied dataset.
- Revenue is net of the transaction-level discount and includes completed orders only; returned orders are excluded rather than modeled as negative revenue.
- There is no authentication or multi-user deployment hardening. The server binds to localhost.

## Development note

AI assistance used: ChatGPT/Codex to interpret the brief, design the data flow and deterministic intent mapping, and draft the implementation and tests. Development issues encountered: the DOCX attachment is a ZIP-based Office document and had to be parsed as such; the supplied CSV contains a returned transaction, a zero-quantity row, and a completed row with zero unit price. These were handled through explicit import validation and audit counts. Debugging was based on inspecting the source document and CSV schema and adding test cases around supported and rejected requests. With another day, I would add more flexible date/filter parsing, richer data-quality reporting, and deployment security and observability.
